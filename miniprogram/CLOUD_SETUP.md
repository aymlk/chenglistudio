# 云开发部署指南（小程序内置管理后台）

把作品数据搬到微信云开发后，**在手机上打开小程序就能发作品，只有管理员能进**，
顾客无感知、也不用重新发版。个人主体也能用云开发，**免服务器、免域名备案、免 HTTPS 白名单**。

> 代码改动已全部完成，本指南只需在「微信开发者工具」里点几下。

---

## 第 0 步：确认环境、拿到环境 ID（2 分钟）

**不用纠结打开哪个目录**，用这个办法一次确认：

1. 用**微信开发者工具**打开项目（打开 `miniprogram` 目录或项目根目录都可以）。
2. 顶部工具栏点 **「云开发」** 按钮。
3. 如果能打开云开发控制台、看到你刚开通的环境 → **说明当前 AppID 与云环境是匹配的**，就用这个窗口继续。
   - 如果提示「未开通」，说明这个 AppID 下没开云开发，换另一个目录打开项目再试。
4. 在云开发控制台**左上角**就能看到**环境 ID**（形如 `photography-9abcde`），点一下可复制。

> 环境 ID 也可以在：云开发控制台 → **设置** → **环境 ID** 找到。

---

## 第 1 步：填入环境 ID

打开 `miniprogram/src/config.ts`，把环境 ID 填进去：

```ts
export const CLOUD_ENV = 'photography-9abcde' // 改成你的环境 ID
```

> 留空时小程序自动使用静态 `works.ts`，照常运行，所以没配之前也能预览。

---

## 第 2 步：上传部署云函数（关键步骤）

> 已自动配置好 `cloudfunctionRoot`，所以开发者工具能识别云函数目录。
> 若你之前打开过项目，**请先关掉开发者工具再重新打开**（让新配置生效）。

在左侧「资源管理器」找到 `cloudfunctions/`（如果打开的是根目录，路径是 `miniprogram/cloudfunctions/`），
里面四个文件夹会带**云朵图标**。逐个**右键 → 上传并部署：云端安装依赖**：

| 云函数 | 作用 |
|--------|------|
| `addWork` | 管理员发作品（含 openid 白名单校验） |
| `deleteWork` | 管理员删除作品（同样校验白名单） |
| `checkAdmin` | 环境自检（返回是否管理员 + openid + 诊断信息） |
| `seedWorks` | 导入初始 11 组作品 |

**必须选「云端安装依赖」**（不要选"上传并部署：所有文件"），因为我们只提交了 `package.json`，
依赖 `wx-server-sdk` 需要在云端安装。

四个都要上传成功，否则会报「云函数不存在」（发作品的报 `addWork`、删除报 `deleteWork`、自检报 `checkAdmin`）。

---

## 第 3 步：建立数据库集合

云开发控制台 → **数据库** → 新建集合：

| 集合名 | 用途 | 权限类型（下拉里选） |
|--------|------|----------------------|
| `works` | 存放作品 | 「**所有用户可读**」（第 3 项，描述"商品信息、新闻列表等"） |
| `admins` | 管理员 openid 白名单 | 「**所有用户不可读写**」（第 4 项，描述"敏感信息，如仅管理员可读写"） |

**为什么不给客户端写权限**：写入全部走云函数，云函数以管理员权限操作、**不受这里限制**。
顾客端只需要读，所以客户端一律不给写权限——这样即使有人反编译小程序，也无法绕过
`admins` 白名单直接往库里塞数据。

---

## 第 4 步：环境自检，拿到你的 openid（新增，最省事）

1. 重新构建并预览（`npm run dev:weapp` 或 `build:weapp`）。
2. 在模拟器/真机打开小程序，**连点「作品」标题 5 次**进入管理端。
3. 点 **「环境自检（云函数 / 我的 openid）」**：
   - 显示「云函数已连通 ✓」+ openid → 云函数部署成功
   - 显示红色失败信息 → 云函数没部署好，回到第 2 步
4. 点 **「点击复制 openid」**。

---

## 第 5 步：把自己加为管理员

云开发控制台 → **数据库** → `admins` 集合 → **新建记录**，添加字段：

```json
{ "openid": "oABC123xxxx你的openid" }
```

> 字段名必须叫 `openid`，值填第 4 步复制的那一串。

再点一次「环境自检」，显示 **「已授权 ✓」** 即成功。

> 只有 `admins` 里的 openid 才能写入，别人即使误入管理端也写不进数据。
> 要加第二个管理员，就再往 `admins` 加一条 openid 记录。

---

## 第 6 步：导入初始作品（仅首次）

管理端点 **「导入初始 11 组作品（仅首次）」** → 提示「导入完成」。
返回作品区即可看到 11 组作品已从云端加载。

之后日常发作品：管理端 → 填表单 → 选图/视频（自动传云存储）→ 点「发布作品」，
**顾客立即看到，不用电脑、不用重新发版**。

---

## 第 7 步：云存储权限（让顾客能看到图）

云开发控制台 → **存储** → **权限设置** → 改为「**所有用户可读，仅创建者可读写**」。

> 注意这里和数据库的取舍**相反**：管理员在手机上选图后，是由小程序客户端直接把文件传到云存储的，
> 所以云存储必须允许客户端写入；而顾客只要「可读」就能看到图。
> （写入方是管理员自己创建的文件，仍属于"创建者可读写"。）

---

## 第 8 步：重新构建

改了 `config.ts` 后必须重新构建：

```bash
cd miniprogram
npm run dev:weapp     # 开发预览（watch 模式，推荐）
# 或
npm run build:weapp   # 产出 dist，用于上传发布
```

---

## 常见问题排查

| 现象 | 原因与解决 |
|------|-----------|
| 右键没有「上传并部署」 | `cloudfunctionRoot` 未生效 → **重启开发者工具**；或打开目录不对 |
| 自检报「云函数调用失败」 | 三个云函数未全部部署；或部署到了别的环境（云开发控制台左上角可切环境） |
| 发布作品提示「无权限」 | `admins` 集合里没有你的 openid，或字段名不是 `openid` |
| 导入/发布成功但顾客看不到图 | 云存储权限没改成「所有用户可读」 |
| 作品区还是静态那 11 组 | 云端 `works` 集合为空 → 先跑第 6 步导入 |
| 提示「环境不存在」 | `config.ts` 的 `CLOUD_ENV` 填错，或该环境不属于当前 AppID |

---

## 日常维护

- **新增作品**：管理端发布，存云端。
- **删除作品**：管理端 → 展开「**管理已有作品**」→ 点作品右侧的垃圾桶图标 → 确认即删（顾客端立即消失）。
- **编辑已有作品**：暂未支持，可删掉重发，或直接在云开发控制台 `works` 集合里改。
- **换环境 / 多人协作**：改 `config.ts` 的 `CLOUD_ENV`；多管理员就在 `admins` 多加几条 openid。
- **未配置云时**：`CLOUD_ENV` 留空即回退静态数据，顾客无感。
